# GUI-test — чек-лист кнопок 1C Log Analyzer

Документ для быстрой повторной проверки GUI. Проверка выполняется на собранном
`dist\1C_Log_Analyzer\1C_Log_Analyzer.exe` и/или на исходниках
(`python ics_log_analyzer.py`). Кнопки, работающие с ClickHouse, без сервера
должны показывать понятный диалог ошибки, а не падать.

## 1. Как повторить проверку

```powershell
# Сборка
cmd /c build.bat

# Все тесты (offline)
python -m pytest -q -k "not TestLiveClickHouse"

# Только кнопки GUI: каждый Button/TButton нажимается через Tk,
# ClickHouse заменён FakeAdapter — сервер не нужен
python -m pytest test_gui_buttons.py -q

# Ручной запуск собранного приложения
.\dist\1C_Log_Analyzer\1C_Log_Analyzer.exe
```

Автотест `test_gui_buttons.py` проверяет фактическое нажатие кнопок, а не только
наличие обработчиков. Для live-проверки с реальным ClickHouse см.
[docs/TESTING.md](docs/TESTING.md) §4.

## 3. Вкладка «Загрузка»

| Кнопка | Что делает | Как проверить |
| :--- | :--- | :--- |
| **Настройки ClickHouse…** | Открывает модальный диалог: хост, порт, база, пользователь, пароль. После «Сохранить» применяет настройки и запускает проверку подключения. | Изменить хост, сохранить; в статус-баре появляется результат проверки. «Отмена» не меняет настройки. |
| **Проверить подключение** | В фоновом потоке проверяет доступность ClickHouse. | При доступном сервере — «ClickHouse доступен.»; иначе — диалог с подсказкой про сервер и `docs/CLICKHOUSE.md`. |
| **Проверить схему** | Только читает схему (`validate_schema`), ничего не создаёт и не удаляет. | Статус «Схема готова…» или диалог с описанием несоответствия. |
| **Выбрать папку с логами** | Открывает выбор каталога, показывает путь и число `*.log` (если в корне нет — считает вложенные). | Выбрать папку: путь и «Файлов: N» обновляются. |
| **Загрузить и распарсить** | Резервный режим: разбирает логи в память, без ClickHouse. Блокирует кнопки, показывает indeterminate-полосу, затем заполняет четыре вкладки. | Без папки — предупреждение. С папкой — «Формат…», «Событий: N», источник «память». |
| **Загрузить в ClickHouse (LogT)** | Проверяет папку и dataset, идемпотентно создаёт схему и импортирует логи через LogT в фоне. Показывает этап, `Файлов: X/Y`, процент и полосу; при неизвестном `total`/проценте — indeterminate-fallback (см. §13). | Без папки/датасета — предупреждение. При успехе — полоса 100 %, «Этап: Готово», диалог «Готово», источник переключается на ClickHouse, вкладки обновляются. |
| **Точный прогресс (подсчёт строк, медленнее старт)** | Чекбокс (включён по умолчанию): просит LogT заранее посчитать строки, чтобы полоса была определённой. Значение читается до старта импорта. | Снять галочку — импорт стартует быстрее, но при неизвестном проценте полоса становится неопределённой, а «Файлов: —». |
| **Отменить** | Доступна только во время импорта; запрашивает отмену через `threading.Event`, блокирует себя и меняет этап на «Остановка LogT…». | Во время импорта кнопка активна; после нажатия stage «Остановка LogT…», статус «Отмена запрошена…», кнопка disabled. Молчащий LogT отменяется ≤2 с: `busy=False`, кнопки загрузки снова активны, полоса остановлена, этап «Импорт отменён». |
| **Применить** | Читает фильтры (пользователь, событие, поиск, даты) и обновляет все четыре вкладки. | Ввести пользователя, нажать: данные и запросы используют этот фильтр, статус «Фильтры применены.». |
| **Сбросить** | Очищает все поля фильтров и обновляет вкладки. | Все пять полей пусты, фильтры сброшены. |

Даты принимаются в формате `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ`; некорректная дата
игнорируется.

Ошибка импорта (включая сбой на этапе схемы) показывается немодальным диалогом
с копируемыми деталями — см. §11.

## 11. Диалог ошибки импорта

Ошибка импорта в ClickHouse (и на этапе схемы, и при ненулевом коде возврата
LogT) показывается не модальным `messagebox`, а отдельным **немодальным** окном
«Ошибка импорта». Главное окно при этом остаётся доступным: можно прочитать
отчёт, скопировать его и запустить импорт заново. Диалог не вызывает
`grab_set`/`wait_window`.

| Элемент | Что делает | Как проверить |
| :--- | :--- | :--- |
| Заголовок и краткий текст | Показывают этап (`Подготовка`, `Подготовка схемы ClickHouse`, `Импорт LogT`) и сообщение об ошибке. | Запустить импорт с недоступным ClickHouse: в шапке — этап, ниже — причина. |
| Область деталей | `tk.Text` только для чтения, но текст выделяется мышью: этап, dataset, папка с логами, код возврата LogT, длительность, путь к журналу `trace-vrs-*.log` (или «не найден в …»), последние строки `stderr`/`stdout`. | Выделить и скопировать фрагмент вручную — текст не редактируется. |
| **Скопировать детали** | Кладёт все детали в буфер обмена и подтверждает: «Детали скопированы в буфер обмена.». | Нажать, вставить в блокнот: весь отчёт на месте. |
| **Закрыть** (или `Esc`, или `X`) | Закрывает окно; повторное открытие ошибки заменяет старый отчёт. | `Esc` и крестик закрывают окно, приложение работает дальше. |

Пароль ClickHouse не попадает ни в шапку, ни в детали, ни в буфер обмена:
текст проходит через `logt_adapter.redact` (и сообщение, и хвосты
`stderr`/`stdout`). Путь к журналу ищется в worker-потоке, а не в главном.

## 13. Прогресс и отмена импорта

В P1-04 полоса импорта стала determinate (с известным процентом). Типизированные
события `ImportProgress` приходят из адаптера (`on_progress`) и складываются в
общую очередь GUI. `ResultDispatcher.drain(...)` с
`coalesce_kinds={"import_progress"}` оставляет только последний снимок и
применяет его **до** `import_done`.

### 13.1. Что показывает вкладка «Загрузка»

```text
[Этап: Обработка логов…]          [Файлов: 3/12]        [25 %]
[██████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░]
```

| Элемент | Значение |
| :--- | :--- |
| **Этап** | Короткий текст текущей стадии: «Подготовка», «Проверка схемы ClickHouse…», «Сканирование», «Обработка логов», «Вставка», «Подсчёт строк», «Готово». Без `[INFO]` и переводов строк. |
| **Файлов** | `X/Y`, если адаптер знает оба числа; `X`, если известно только текущее; `—`, если процент неизвестен. |
| **Процент** | `P %` при известном проценте, пусто при неизвестном. |
| **Полоса** | `determinate` с `maximum=total` (или 100, если известно только `percent`); `indeterminate` при `percent=None`. |

Проверка вручную:

1. Выбрать папку и dataset, нажать «Загрузить в ClickHouse (LogT)».
2. Сразу после старта — «Этап: Проверка схемы ClickHouse…», полоса
   неопределённая (схема проверяется до запуска LogT).
3. При включённом чекбоксе появляются «Файлов: X/Y» и «P %», полоса идёт
   вперёд и не откатывается.
4. Снять чекбокс и повторить: старт быстрее, при неизвестном проценте полоса
   снова неопределённая, «Файлов: —».
5. По завершении — 100 %, «Этап: Готово», статус «Готово. Импортировано
   строк: N».
6. Повторный импорт начинается с 0 %, а не с 100 %.
7. Нажать «Отменить» во время импорта: кнопка становится disabled, этап
   «Остановка LogT…», статус «Отмена запрошена…». Молчащий LogT отменяется
   ≤2 с; после ответа — «Импорт отменён», `busy=False`, кнопки загрузки снова
   активны, полоса остановлена (determinate).
8. Ошибка импорта: этап с пометкой «— ошибка», статус «Ошибка импорта.»,
   немодальный диалог «Ошибка импорта» с кнопками «Скопировать детали» и
   «Закрыть» (см. §11). После закрытия повторный импорт начинается с 0 %.
9. Сразу после ошибки повторить импорт: виджеты сбрасываются на «Этап: —»,
   «Файлов: —», 0 %, и успешный прогон снова доходит до 100 %.

## 14. Экспорт, пресеты и расширенные фильтры (v0.3)

### 14.1. Вкладка «Экспорт»

| Элемент | Что делает | Как проверить |
| :--- | :--- | :--- |
| **Формат** | CSV / JSON / XLSX | Выбрать каждый формат и экспортировать одну и ту же таблицу. |
| **Таблица** | Ошибки / Пользователи / Обзор / Производительность | Для агрегатов доступна только текущая таблица. |
| **Текущая таблица** | Ровно строки, показанные в дереве (для ошибок — текущая страница) | Сравнить число строк в файле с таблицей. |
| **Все отфильтрованные** | Постраничная выгрузка ошибок (`count_errors` + `query_errors`) или всех пользователей (`query_users`) | Задать фильтр, нажать «Экспортировать…», дождаться статуса «Сохранено: … (N строк)». |
| **Прогресс/Отмена** | Фоновая выгрузка не блокирует Tk; кнопка «Отменить экспорт» | Во время большой выгрузки нажать отмену: статус «Экспорт отменён.», кнопки снова активны, `.part`-файла не остаётся. |
| **Лимиты** | ≥10 000 строк — подтверждение; >100 000 — только после согласия на усечение | Проверить диалоги; при отказе файл не создаётся. |

Ограничения, которые GUI показывает явно:

- «Обзор» и «Производительность» — агрегаты top-N; «Все отфильтрованные» для
  них блокируется с пояснением, а не выгружает молча top-N.
- В режиме памяти доступна только текущая таблица: фильтры ClickHouse к
  памяти не применяются.

CSV остаётся `utf-8-sig`; JSON — UTF-8 без BOM с `schema_version`,
`exported_at`, `row_count`, `columns`, `rows`; XLSX содержит листы «Данные» и
«Метаданные». Ячейки, начинающиеся с `=`, `+`, `-`, `@`, TAB или CR,
экранируются апострофом (защита от формул).

### 14.2. Пресеты фильтров

Пресеты лежат в `<project>/config/presets.json` (не в `%APPDATA%`). Пароль,
host и log_dir в файл не попадают; `dataset` по умолчанию не сохраняется.

| Кнопка | Проверка |
| :--- | :--- |
| **Сохранить как…** | Ввести имя, применить фильтры, перезапустить приложение — пресет есть в списке, фильтры восстановлены, но запрос автоматически не выполняется. |
| **Загрузить** | Выбрать пресет → поля заполняются, вкладки обновляются. |
| **Удалить** | Подтверждение → пресет исчезает из списка и из файла. |
| **Сбросить все…** | Два подтверждения → файл перезаписан пустым валидным документом, старый заархивирован. |

Битый или слишком новый `presets.json` не роняет приложение: статус рядом с
списком объясняет причину, остальные пресеты доступны; при `schema_version > 1`
запись запрещена.

### 14.3. Расширенные фильтры

Вторая строка фильтров: **Процесс** (`p:processName` → `db_name`, регистр не
важен), **AppID** (ищется по тексту `event_string` — сузьте даты),
**Мин. длительность, мс** (`duration_us >= N*1000`). Все значения уходят в
ClickHouse query-параметрами; SQL-инъекция невозможна. Подсказка в UI
предупреждает, что минимальная длительность скрывает события без `Duration`,
включая ошибки.

Автотесты: `test_gui_buttons.py` (фильтры, пресеты, экспорт), `test_export.py`,
`test_presets.py`, `test_logt_sql_safety.py`, `test_ics_log_analyzer.py`,
`test_gui_error_paths.py`.

```powershell
python -m pytest test_gui_buttons.py test_gui_error_paths.py test_ics_log_analyzer.py -q
python -m pytest test_export.py test_presets.py test_logt_sql_safety.py -q
```
