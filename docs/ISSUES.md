| BUG-006 | `logt_adapter.py` / `logt_schema.py` | В собранном `.exe` `sys.executable` — GUI-бинарник `1C_Log_Analyzer.exe`, а `REPO_ROOT` указывает в `_internal`, где нет `vendor/logt`; импорт через LogT из `.exe` не работает. Обход: внешний Python 3.11+ (путь — в `LOGT_PYTHON`, иначе `python`/`python3`/`py` из `PATH`) и `LOGT_ROOT` на каталог LogT с `src/main.py`; preflight `check_logt_runtime` показывает ошибку до старта импорта. Полное исправление (встраивание интерпретатора и `vendor/logt` в бандл) не входит в v0.2. | Высокий | Открыт (preflight и обход — v0.2; запуск без внешнего Python — отдельная задача) |
| BUG-007 | `logt_adapter.py` | `_is_connection_error` считал сетевой любую ошибку-наследника `OSError`, включая `FileNotFoundError` и `PermissionError`; локальная ошибка файла показывалась как «ClickHouse недоступен». | Средний | Закрыт (учитываются только сетевые типы и network-errno; тесты `test_logt_adapter_errors.py`) |
| BUG-008 | `logt_adapter.py` | Повреждённый `config/clickhouse.local.json` вызывал рекурсию `load_local_config` → `redact` → `load_local_config` и `RecursionError` вместо пустого конфига. | Высокий | Закрыт (re-entry guard в `load_local_config`; тест `test_logt_adapter_errors.py`) |
