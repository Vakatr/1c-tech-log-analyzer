# План развития

> MoSCoW: **Must** — без этого релиз не имеет смысла; **Should** — важно, но можно
> отложить; **Could** — желательно; **Won't** — сознательно не делаем.
> Долг и баги — [ISSUES.md](ISSUES.md), история изменений — [../CHANGELOG.md](../CHANGELOG.md).

## 1. Готово

Разбор логов в память; импорт через LogT; вкладки из ClickHouse; серверная
агрегация; параметризованные запросы; идемпотентная схема без `DROP` на
автоматических путях; защита кредов; CSV-экспорт; сборка `.exe`; асинхронные
вкладки режима памяти; единая настройка `logging`; CI с offline-тестами и
сборкой `.exe`; контрактный тест схемы LogT; проверяемый DACL для временного
`config.json`; устойчивое извлечение описания ошибок с пометкой сокращений;
экспорт CSV/JSON/XLSX с атомарной записью и защитой формул; постраничная
выгрузка всех ошибок/пользователей; пресеты фильтров; фильтры процесса, AppID и
минимальной длительности.

## 5. Порядок и критерии

1. Стабилизация: `ISSUES.md`, порядок в репозитории.
2. UX импорта: прогресс, отмена, понятные ошибки.
3. Экспорт: JSON/Excel, пресеты фильтров.
4. Аналитика: пороги, аномалии, сравнение dataset-ов.
5. Инфраструктура: CI, затем веб/мониторинг.

- Offline-набор всегда зелёный; live — перед релизом.
- Никакого `DROP` на автоматических путях.
- Новая зависимость — только с записью в `.spec`.
- Новая возможность — с документацией в том же коммите.
